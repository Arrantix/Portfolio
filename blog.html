01 / AI & games

Turning a game into a learning task.

A game has rules, possible moves, and an outcome. In reinforcement learning, it can be described as a sequence of states, actions, and rewards. An agent tries actions and uses feedback to inform future decisions.

In Deep Q-Learning, a neural network estimates the value of possible actions. Experience replay reuses previous experiences; a separate target network can help stabilize training. Results depend in part on how the state and reward are defined.

Tetris and checkers make these questions tangible: What information does the agent need? What do we reward? And is it learning the behavior we actually intended?

02 / Delivery

An app has to reach its users.

For PC Dashboard, the Windows executable is part of the product. It bundles the application so it can run without a local Python installation.

GitHub Actions checks the Windows build on code changes and creates an executable with a SHA-256 checksum for releases. That keeps source code, build, and download connected.

I state the limits as clearly as the features: the executable is not signed, and GPU readings depend on available NVIDIA telemetry. Good delivery includes these details.

03 / Correctness

A bug fix needs a counterexample.

During my internship, I investigated defects in a larger Python codebase where different plausible calculations produced conflicting results. The first step was to make the intended rule explicit.

I reproduced the edge case, corrected the calculation, and added regression tests. The tests needed to capture the rule rather than merely repeat the implementation.

A fix is convincing when you can explain why the old case failed and what prevents it from returning.

04 / Automation

Automation needs a stop condition.

During my internship, I worked on automated decisions in team software. The underlying data can change state before the action runs; the process may then complete technically while producing the wrong outcome.

I checked those state changes at the decision point, moved hard-coded rules into configuration, and tested the boundaries.

A safe exit is part of the feature: when the prerequisites no longer hold, the system should visibly do nothing.

05 / Frontend

A layout needs room to adapt.

A responsive layout adapts to its content and the available space. Simply making everything smaller on a small screen is not enough.

Columns can stack, text needs room to wrap, and navigation needs to stay reachable. Long German words make a useful practical test.

Readability, keyboard access, and reduced motion are part of the design. They are best checked with real content in the browser, rather than left until the end.
